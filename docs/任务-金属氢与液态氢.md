## 1. 现状（已核对，勿凭旧记忆）

氢的注册在 **patch 层**（不是 gtnecore 主代码），文件 `src/patch/java/common/data/materials/ElementMaterials.java:340-344`：

```java
Hydrogen = new Material.Builder(GTCEu.id("hydrogen"))
        .gas()
        .color(0x0000B5)
        .element(GTElements.H)
        .buildAndRegister();
```

**本仓库已有的先例（照抄它）**——液氦 `ElementMaterials.java:346-356`、液氧 `586-597`：

```java
Helium = new Material.Builder(GTCEu.id("helium"))
        .gas(new FluidBuilder().state(FluidState.GAS).customStill())
        .plasma()
        .liquid(new FluidBuilder()
                .temperature(4)                     // 沸点，显式写
                .color(0xFCFF90)
                .name("liquid_helium")
                .translation("gtceu.fluid.liquid_generic"))   // 显示 "Liquid Helium"
        .element(GTElements.He)
        .buildAndRegister();
Helium.getProperty(PropertyKey.FLUID).setPrimaryKey(FluidStorageKeys.GAS);   // ← 关键
```

⚠ **`setPrimaryKey(GAS)` 是生死线**：GTCEu 的 `Material.getFluid()` 取的是**主动体（primaryKey）**。氢现在是气态主动体，`getFluid()` 返回气态氢——全 mod（GTCEu 化学配方、本 mod 发射台配方）都靠它。加了 `.liquid()` 却不写这行，主动体可能变成 LIQUID，所有气态氢配方集体失配。

## 2. 任务 A：扩展 Hydrogen 材料定义

改 `src/patch/java/common/data/materials/ElementMaterials.java` 的 Hydrogen 块：

```java
Hydrogen = new Material.Builder(GTCEu.id("hydrogen"))
        .gas()
        .liquid(new FluidBuilder()
                .temperature(20)                    // 液氢沸点 20K（对照：液氦 4、液氧 85）
                .color(0x86C8FF)                    // 浅蓝，可自调；液氧用 0x6688DD 可参考
                .name("liquid_hydrogen")            // 流体 id = gtceu:liquid_hydrogen
                .translation("gtceu.fluid.liquid_generic"))
        .ingot()                                    // INGOT 属性 + 自动补 DUST 属性
        .color(0x0000B5)                            // 原色不动
        .iconSet(METALLIC)                          // 可选：金属光泽（见 §6 注意事项）
        .appendFlags(EXT2_METAL, GENERATE_RING, GENERATE_FOIL, GENERATE_GEAR,
                GENERATE_SMALL_GEAR, GENERATE_ROUND)
        .element(GTElements.H)
        .buildAndRegister();
Hydrogen.getProperty(PropertyKey.FLUID).setPrimaryKey(FluidStorageKeys.GAS);
```

落地效果：

- **物品**（GTCEu 自动生成，无需注册表/贴图/lang 手写）：锭、粒、块、粉/小撮粉/微粉（`.ingot()` 固有行为，会自动补 DUST 属性）、板、杆、长杆、螺栓+螺丝、环、箔、齿轮、小齿轮、圆盘。
- `EXT2_METAL` 是 `GTMaterials` 里的 `List<MaterialFlag>`（= 板 + 杆 + 长杆 + 螺栓螺丝），该文件已 `static import GTMaterials.*`，直接可用（现文件里 Am/Eu/Au 等就是这种写法）。
- **不要**加：`BLAST`（会带 EBF 熔炼路线）、`NO_SMASHING`（会换掉粉→锭路线）、`GENERATE_ROTOR/SPRING/FINE_WIRE/DENSE`（需要额外属性或与"金属氢"无关；要加先议）。`.ingot()` 默认是 `ingot(1,1)` 档（采集等级 1），要更高写 `.ingot(2)`。
- 名字/lang 都不用动：材料名 `material.gtceu.hydrogen` 已在 GTCEu lang 里；液体名走 `gtceu.fluid.liquid_generic` 模板（"Liquid Hydrogen"）；物品名 GTCEu 运行时生成。

## 3. 任务 B：封死 6 处流体固化（本次的核心正确性要求）

**机制（字节码确认）**：GTCEu 生成 `solidify_*` 自动配方的前提是 `material.hasFluid() && FLUID 属性.solidifiesFrom(amount) 非空`；`FluidProperty.solidifiesFrom()` 在 `solidifyingFluid == null` 时会**惰性取该材料的 LIQUID 流体**。所以氢一旦同时有"液氢 + 锭"，框架就会自动冒出 6 条固化配方——全部要封。

两个 patch 类、共 6 处（都在 `com.gregtechceu.gtceu.data.recipe.generated` 包，**都已在 patch 层**，用 `grep -n "solidifiesFrom("` 可全部定位）：

| 文件 | 行号 | 配方 id | 模具 |
|---|---|---|---|
| `MaterialRecipeHandler.java` | 339-349 | `solidify_hydrogen_to_ingot` | 锭模 |
| 同上 | 520-531 | `solidify_hydrogen_to_nugget` | 粒模（×9） |
| 同上 | 579-589 | `solidify_hydrogen_block` | 块模 |
| `PartsRecipeHandler.java` | 229-241 | `solidify_hydrogen_gear` / `solidify_hydrogen_small_gear` | 齿轮/小齿轮模 |
| 同上 | 307-319 | `solidify_hydrogen_to_plate` | 板模 |
| 同上 | 452-463 | `solidify_hydrogen_to_rotor` | 转子模 |

**建议实现**：在 `MaterialRecipeHandler` 里加一个包私有判定（两个类同包，PartsRecipeHandler 直接 `MaterialRecipeHandler.allowFluidSolidification(...)` 调用即可，单一真源）：

```java
/**
 * GTNEcore：金属氢（H 的锭）是极高压产物，不是冷冻液氢浇出来的——禁止一切流体固化配方。
 * 对应上游 6 处 solidify_* 生成点（MaterialRecipeHandler ×3 + PartsRecipeHandler ×3）。
 */
static boolean allowFluidSolidification(@NotNull Material material) {
    return material != Hydrogen;   // 本文件已 static import GTMaterials.*
}
```

然后 6 处 `if (material.hasFluid()) {` 改为 `if (material.hasFluid() && allowFluidSolidification(material)) {`。

- 只改这 6 处（均带 `solidifiesFrom(` 调用）；**不要**动同文件里其它 `material.hasFluid()`（有别的用途）。
- 以后要扩黑名单把判定改成 `Set` 即可。
- patch 层文件**不能引用 gtnecore 主类**（patch 的 compileClasspath 不含 main 输出），判定只能写在 patch 层内部——所以才用"直接比材料实例"的写法。

## 6. 已知坑 / 注意事项

- `setPrimaryKey(FluidStorageKeys.GAS)` 漏写 = 所有气态氢配方失配（灾难级），务必写 + 验证第 3、4 条。
- `.liquid()` 的 `FluidBuilder` 要显式 `.temperature(...)`（液氦 4 / 液氧 85 都写了；不写会走 GTCEu 的推断温度）。
- `iconSet(METALLIC)` 是可选加成：它会让**现有气态/液态氢的流体贴图底纹**一起变（流体贴图由 iconSet 派生）。想要气态氢外观完全不变就去掉这行——金属感可以靠 `secondaryColor` 微调。此点**建议交给用户看一眼再定**。
- 封固化只封"氢"，不要顺手改其它材料的行为。
- patch 层改的是特供 GTCEu（jarjar 嵌入，玩家禁装官方 GTCEu）——物品/流体随 patch 一起发布，无需额外资产文件（贴图/模型/lang 全部 GTCEu 运行时生成）。
- `.ingot()` 会顺带带出 MACERATE/SMELT 等自动配方；粉本身无来源（创造获取），不影响。
