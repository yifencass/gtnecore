# 匠魂（Tinkers' Construct）材料系统研究

> 2026-08-27 · GTNEcore 匠魂内容前置研究。
> 对象：Tinkers 1.20.1 构建 7449219（curse 74072）+ Mantle 7563777（curse 74924），
> dev 环境 deobf jar 反编译 + 数据包 JSON 直读；GTSE（gregic_tinkering-1.3.0，
  已废弃但机制可参考）桥接思路一并归纳。

## 一、三层架构总览

```
数据层（datapack，纯 JSON）                代码层（mod 初始化）              客户端层
data/<ns>/tinkering/materials/            IMaterialRegistry                assets/<ns>/tinkering/materials/
├── definition/<id>.json  材料定义         ├── registerStatType(统计类型)    └── <id>.json  渲染信息
├── stats/<id>.json       各部位数值       ├── MaterialStatsManager(加载)
└── traits/<id>.json      特性列表         └── ModifierManager(修饰器注册)   灰度模板 + 调色板重着色
```

- 材料**没有注册表条目**：材料是数据包资源（服务端加载、同步包 `UpdateMaterialsPacket`
  系列下发客户端），代码层只注册**统计类型**和**修饰器**
- 一个"材料"= 三份 JSON（definition + stats + traits）+ 一份渲染 JSON + 灰度部件贴图

## 二、数据包三件套（以 iron / manyullyn 为例）

### definition/iron.json —— 材料定义
```json
{ "craftable": false, "hidden": false, "sortOrder": 0, "tier": 2 }
```
- `craftable`：零件加工台直接可用（材料物品=零件）
- `tier`：材料分级（匠魂内部 tier，控制零件加工台/合成可用性），`sortOrder` 排序

### stats/iron.json —— 数值（按部位统计类型分组）
```json
{ "stats": {
    "tconstruct:head":   { "durability": 250, "melee_attack": 2.0, "mining_speed": 6.0, "mining_tier": "minecraft:iron" },
    "tconstruct:handle": { "durability": 0.1, "melee_damage": 0.0, "melee_speed": 0.0, "mining_speed": 0.0 },
    "tconstruct:grip":   { "accuracy": 0.0, "durability": 0.1, "melee_damage": 2.0 },
    "tconstruct:limb":   { "accuracy": 0.0, "draw_speed": -0.2, "durability": 250, "velocity": 0.1 },
    "tconstruct:binding": {}, "tconstruct:maille": {}, "tconstruct:plating_boots": { "armor": 2.0, "durability": 195 }, ...
} }
```
- head=主工作部件（耐久/攻速/挖掘等级），handle=倍率修正（小数加减），limb/grip=远程，
  plating_×6=护甲四件+盾+板甲，binding/maille=无属性槽
- manyullyn 顶级参考：head 1250 耐久 / 3.5 攻 / 6.5 速 / netherite 挖掘等级

### traits/iron.json —— 特性
```json
{ "default": [ { "level": 1, "name": "tconstruct:magnetic" } ],
  "perStat": { "tconstruct:armor": [...], "tconstruct:skull": [...] } }
```
- `default`：整把工具生效；`perStat`：仅该部位用此材料时生效（按 stat 类型细分）

## 三、代码层 API

- **`IMaterialRegistry`**（`MaterialRegistry.get()`?）：`registerStatType(MaterialStatsId, type)`、
  `getMaterial/getMaterialStats/getDefaultTraits/isInTag` 等；**addon 主要用它注册自定义统计类型**
- **`MaterialsLoadedEvent`**（library/events）：材料数据加载完成事件，可后处理
- **`ModifierManager`**：修饰器（trait 的载体）注册/查询；自定义 trait = 注册 Modifier +
  材料JSON引用。修饰器本体是代码类（行为），JSON 只声明 level
- 加载器：`MaterialManager`（definition）/ `MaterialStatsManager`（stats）/
  `MaterialTraitsManager`（traits），各自带网络同步包

## 四、内置统计类型与 GTSE 扩展

| 类型 | 部位 | 关键字段 |
|---|---|---|
| `tconstruct:head` | 工具头 | durability / mining_speed / melee_attack / mining_tier |
| `tconstruct:handle` | 手柄 | durability(倍率) / melee_speed / melee_damage / mining_speed |
| `tconstruct:binding` | 绑定 | 无字段（Statless） |
| `tconstruct:limb` / `grip` | 弓臂/握把 | draw_speed / velocity / accuracy / melee_damage |
| `tconstruct:plating_helmet..boots` / `plating_shield` / `armor_plating` | 护甲 | armor / durability |
| `tconstruct:maille` / `armor_maille` | 锁环 | 无字段 |
| `tconstruct:skull` | 头颅 | （拟态用） |

**GTSE 自定义了 4 种**（`materials/stats/`）：`BatteryMaterialStats`（电池部件）、
`EngineMaterialStats`（引擎）、`PlungerHeadMaterialStats`、`SoftMalletHeadMaterialStats`
——证明 addon 挂自定义 stat 类型做**科技向工具部件**完全可行。

## 五、渲染系统（对 GT 桥最有价值）

`assets/<ns>/tinkering/materials/<id>.json`：
```json
{ "color": "FF9261CC", "fallbacks": ["metal"],
  "generator": { "supported_stats": [...],
    "transformer": { "type": "tconstruct:recolor_sprite",
      "color_mapping": { "type": "tconstruct:grey_to_color",
        "palette": [ { "grey": 0, "color": "FF000000" }, ..., { "grey": 255, "color": "FFFFFFFF" } ] } } } }
```
- **部件贴图是灰度模板**（灰阶 0-255 七档），材料渲染 = 按调色板重着色生成
- `fallbacks`：无专属贴图时回落到共享模板组（metal/gem/stone...）
- **GT 材料自带颜色**（material color）→ 灰度→彩色调色板可直接从 GT 颜色推导，
  这是批量桥接的渲染基础（GTSE 的 `GregicMaterialRenderInfoProvider` 就是干这个的 datagen）

## 六、物品与获取链

- 工具部件物品携带 `MaterialVariantId` NBT（部件+材料变体）；材料本身不是物品
- 冶炼炉：`tconstruct:melting` 配方（`forge:ingots/xxx` → `forge:molten_xxx` 流体 tag，
  带 temperature/time/byproducts 副产物）；浇铸/铸造台出锭与部件
- `MaterialMeltingRecipe`：按"材料物品变体"熔炼（部件带什么材料就出对应熔液）
- 熔融流体走 **forge 流体 tag**（`forge:molten_iron`）——**GT 材料流体可直接对标**
  （GT 的 molten 材料流体注册进 forge:molten_* tag 即被冶炼炉认可）

## 七、GTSE（gregic_tinkering）桥接思路归纳

- **方向是反向的**：把匠魂金属（slimesteel/amethyst_bronze/pig_iron/manyullyn/
  knightmetal/hepatizon...）注册成 **GTCEu Material**（`registerMetal(MetalItemObject,
  公式...)`，公式用 `Fe?`/`CoAu?`/`Co3?` 占位），使匠魂材料进 GT 化学体系
- 自定义 4 种 stat 类型做"电动/科技工具"（电池、引擎部件）
- datagen provider 一套（材料定义/数值/特性/渲染信息/精灵图各一个 Provider）
- 启示：GT↔匠魂双向都能桥；**我们的方向（GT 材料 → 匠魂材料）它没做**——正好是空位

## 八、GTNEcore 可行路线（建议按序）

**A. GT 材料 → 匠魂材料批量桥**（主力，工程量大头在映射规则）
- 选取子集（按材料 tag/属性：金属/宝石/聚合物）生成 definition/stats/traits 三件套
- stats 映射公式：耐久≈硬度/等级函数、挖掘等级≈GT 工具等级映射（iron→iron, diamond→diamond...）
- trait 挑选：按材料属性（磁性→magnetic、耐火→防火类 trait...）
- 渲染：GT 材料 color → grey_to_color 调色板（GTSE 的 render info provider 可抄思路）
- 熔融：GT 材料流体挂 `forge:molten_*` tag + melting 配方
- 实现方式：**纯数据包 JSON**（gtnecore 直接 ship data/gtnecore/tinkering/materials/）
  或代码生成 JSON——无需动代码层，除非要自定义 stat 类型

**B. GTNEcore 特有顶级材料**（无尽/时间物质/弦/归一物质做顶级匠魂材料）
- 专属 trait 需代码注册 Modifier（行为）+ JSON 引用；数值可按 manyullyn 之上再抬
- 与无尽剑强化、天文观测站内容联动（如"星辉"trait 在天文环境内加成）

**C. 自定义 stat 类型**（GTSE 路线：科技部件——能量部件用 EU 存储等）
- registerStatType + 部件贴图 + 工具定义，工作量最大，价值看玩法设计
