# 线程机制设计 v1(2026-09-05)

> 线程(Thread)= 多方块**同时运行多种配方**;并行(parallel)= 单配方 ×P 放大。
> GTCEu 7.5.3 原版只有并行(ParallelHatch:控制器成型时 `instanceof IParallelHatch` 自动捕获,配方经机器 modifier 链 ×P 放大,时长不变)。
> 参考源码已读:RecipeLogic.java 全文、ParallelLogic、GTRecipeModifiers.hatchParallel、MultiblockControllerMachine、autoAbilities。

## 1. 三品位(玩家视角)

设机器装有:线程仓合计 **T** 线程;并行仓提供 **P** 并行(parallel hatch 的 getCurrentParallel)。

| 品位 | 与并行仓 | 每线程并行 q | 实际总吞吐 | 用途 |
|---|---|---|---|---|
| 线程仓(普通) | **相斥**(有 P 时 P 作废,提示语) | 1 | T 种配方各 ×1 | 多配方并行,不吃并行 |
| 均分线程仓 | 可共存 | `max(1, floor(P/T))` | ≈P(T 种配方分 P 的并行) | 吞吐不变但可分 T 种配方 |
| 倍频线程仓 | 可共存 | P(无 P 时 1) | T×P | 吞吐相乘的狂暴模式 |

普通线程仓与并行仓"相斥" = 机器同时有两者时并行作废(普通仓 tooltip 说明)。

## 2. 执行模型(阶段 1 核心:ThreadRecipeLogic)

`ThreadRecipeLogic extends RecipeLogic`,机器自带。**槽 0 = 父类原状态**(status/progress/duration/lastRecipe 全 @Persisted → UI/JEI/渲染/存档**完全兼容**,不加任何改动);附加槽(1..T-1)为内存态列表。

- 每槽独立流水线:searchRecipe() → 找到 → 放大(见下)→ checkRecipe/matchRecipe(消耗输入)→ setup → handleRecipeWorking 式推进 → 完成产出 → 重搜
- **并行放大**:每槽配方按 q(品位公式)放大,方式与 hatchParallel 同款:`modifyAllContents(×q)` + `eutMultiplier(×q)`、时长不变。放大后的配方**吃 ×q 输入、给 ×q 输出、耗 ×q EU**——输入自然限制槽数(两槽同抢一批料:第一个吃到,第二个搜空,闲置,即"竞争")
- 电量:各槽 EU 按 matchTickRecipe 从能源仓扣;不足 → 槽暂停(复用父类 setWaiting/regress 语义;总 runAttempt 计数可放宽)
- 状态聚合:任一槽工作中 → status=WORKING;全空闲 → IDLE。主槽空闲附加槽工作也要保证不退订(keepSubscribing 覆写)
- 断电 SUSPEND/工作开关(MachineControllerCover)/redstone:作用于全部槽(简化:整机语义)
- 槽 0 的配方选择:与附加槽等价竞争(公平);若槽 0 选到配方 → 父类路径完整可用
