# 0→HV（+少量 EV）早期测试版覆盖审计

> 2026-09-05 · 三路并行取证：① gtnecore 内容按档梳理 ② GTCEu patch 层对早期流程影响
> ③ 整合包解锁节奏。范围：ULV→HV（+EV 边界）；结论分"确证"与"推断"。
> 背景：用户定案早期测试版 = 0→HV，此前投入偏科后期；线程机制等后期内容冻结。

## 一、总论

1. **patch 层对 0→HV 是"零伤害"**（与 vanilla 7.5.3 逐文件 diff 确证）：材料五文件零改动、
   配方层（ore/stone/wood/电路/部件/化学）零改动、机器增删零改动、**世界生成零改动**。
   patch 的全部主题 = 15 档→22 档 + int→long 电压机械重构 + 渲染/稳定性修补。
   0→HV 玩家在 patch 面唯一感知 = 挖机器方块不再 NPE、原始水泵结构放宽（buff）、
   多了 15..21 档内容（看不见）。
2. **gtnecore main 层：0→HV 的生存可玩链极短**——唯一完整"制造→使用"链 =
   LV..IV 能量立方（组装机）。星图/火箭/发射台/观测站等所有机器本体**在 resources 内
   全部没有制造配方**（GTCEu 不会为 addon 机器自动生成组装配方）。
3. **整合包节奏主控不在本工程**：真实 quest/配方注入在整合包层（FTB Quests + KubeJS，
   实例里存在但脚本不在仓库）。GLM §31 曾有用户定位："IV 前早期测试——GTCEu 原版已
   完整覆盖 LV-IV，GTNEcore 侧只需确保自定义机器/物品在正常生存中可获得"——**该承诺
   与现状（机器无配方）冲突，是本审计头号问题**。

## 三、0→HV 缺口清单

### P0 — 生存可玩性直接断点

1. **机器本体全部无制造配方**：发射台、天文观测站、星象编程仪(9 档)、EU 氧分配器、
   重力正常化器、天文/全能维护仓、蒸汽熔炉 64、>IV 能量立方——0→HV 生存只能 /give。
   与 GLM §31"确保正常生存可获得"冲突。**决策点：机器配方由 gtnecore 自给，还是
   交给整合包层（KubeJS/datapack）注入？**
2. **astronomical_finderscope（观测站结构必需建材）无任何配方**——星图链第一环就断：
   空白星图(MV) → 编程仪需 ASTRONOMICAL 环境 → 观测站成型需 finderscope。
3. **代码层配方与 JSON 层重复且矛盾**：GtnecoreAddon.addRecipes 以同 id 生成
   dust/1A/4-64min 版本，JSON 层是 raw ore/部分 2A/8min。实测 JSON 生效（发射台任务
   验证过），但代码层是隐患源（若 JSON 缺失会静默回退到旧内容）。建议把代码层
   发射台/星图块整体移除或加"仅 JSON 缺失时兜底"开关，消除双源。

### P1 — 测试体验/节奏

4. 发射任务 8min/次；失重 SPACE_BONUS（时长×0.25+产出×2）依赖 Ad Astra 轨道维度，
   0→HV 大概率不可达 → 多次测试偏慢。验证 SPACE_BONUS 触发路径是否如设计即可，或
   讨论地面替代激励（设计决策，勿擅动）。
5. LV 档编程仪在档案中无用途（所有写图配方 ≥MV）——测试大纲别排 LV 任务。

### P2 — 潜伏/后期

6. TagLoaderMixin 全局吞 tag 解析失败 → 若低档 tag 缺条目，配方静默消失无日志（潜伏）。
7. 反曲率引擎注释电压（LuV96A=8192 等）与代码 V[LuV]*96 不符——注释残留，后期修。
8. mk2..5 火箭、gt_halo、全部自定义材料/粒子粉无配方（创造/后期素材，符合定位）。
9. 线程 27 仓+熔炉已隐藏（创造页+JEI 双 tag），0→HV 不可见——符合设计。
10. 能量立方 >IV 无配方（纯创造）——测试页别误导。
