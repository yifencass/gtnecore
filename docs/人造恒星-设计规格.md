## 〇、设计前提（已确认，勿改）

1. **不参考现实恒星寿命**。寿命/演化节奏完全由"质量消耗速率"这一条参数控制。
2. **人造恒星是受控环境**。正常运转不会熔毁周围，主动引发超新星也不会损坏周围方块。
   → 因此**不做辐射屏蔽结构**，不因恒星本身对玩家造成伤害。
   （例外：`Neutronium` 材料自带 `radioactiveHazard(10)`，成品搬出机器时仍需穿戴防护。这是材料属性，不是机器泄漏。）
3. **升级与电压阶段无关**。升级只看"恒星质量是否顶到当前约束能力的上限"。
4. **收益重心是物质而非电力**。后续版本还有更逆天的机器，人造恒星独占的是
   **"用氢氦凭空造元素"** 这条语义。黑洞分支的纯发电是其唯一例外。
5. **不需要每个电压阶段攀升一阶**，也不需要每个元素一条配方。配方族固定为 3 条。

## 一、核心机制：约束是容器，质量是水位

整台机器只有一个真正的心跳：**`质量` 与 `约束能力` 的大小关系**。

```
                质量上限 = 约束能力 × ??
                     ↑
     ┌───────────────┼───────────────┐
     │         安全运行区间           │   区间宽度由「约束能力」决定
     └───────────────┼───────────────┘
                     ↓
                质量下限 = 约束能力 × ??
```

| 条件 | 结果 |
|---|---|
| 质量 < 下限 | **坍缩**（事故） |
| 下限 ≤ 质量 ≤ 上限 | 正常运转 |
| 质量 > 上限 | **轻而易举**（事故） |
| 质量顶到上限 | **升到下一级恒星**（不自动，需玩家持续投料顶上去） |

### 1.1 两条铁律

- **喂猛了就炸**：无脑灌氢氦让质量超过当前约束能力能装下的量 → 轻而易举。
- **降级也炸**：恒星等级掉了而质量没跟着掉，容器相对变小、下限抬高 → 坍缩。

推论：**正常路线只有"超新星从 0 开始"这一条**。这就是"重新培育"的真正含义 ——
它不是惩罚设计，而是机制必然。意外导致超新星时，玩家损失的是**已经投入的整轮攀升时间**。

### 1.2 "轻而易举"是什么

社区梗，指代本设计中**因操作失误导致的事故**（源自 IC2 核电"运行轻而易举"后被炸死+拼接
HBM 核弹弹坑的往事）。本设计中它是**玩家自己造成的**，不是随机事件：

- 灌过头 → 轻而易举
- 降级 → 坍缩
- 两种事故都让恒星回到 I 级、质量清零，从头培育

## 二、恒星攀升路线

**UHV 阶段即可看到完整清单**，但做不出上面的 —— 攀升门槛不是电压阶段，而是
**约束能力的实际水平**（见 §5）。

### 2.0 第 0 级：星云团（起始态）

恒星不是一放下去就成了红矮星的。**刚成型时它就是一团星云**：

| 项 | 值 |
|---|---|
| 编号 | 0 |
| 名称 | 星云团 |
| 产能 | **无**。不发电、不产等离子体、不出任何东西 |
| 视觉 | 稀薄尘气，球体几乎不发光 |
| 脱离条件 | 质量 ≥ 红矮星门槛 |

这一级存在的意义是**把"从零培育"这段过程显式化**：玩家先得往里灌氢氦把质量顶上去，
才第一次看见恒星亮起来。它也是事故与超新星之后的**重置落点**（见 §4）。

### 2.1 攀升路线（I 级起）

| # | 恒星类型 | 光谱型 | 关键解锁 | 质量消耗速率 | 可产元素区间 |
|---|---|---|---|---|---|
| I | 红矮星 | M | 氢→氦聚变发电 | ?? | 3–?? |
| II | 橙矮星 | K | ?? | ?? | 3–?? |
| III | 黄矮星 | G | 主序完成，元素谱扩展 | ?? | 3–?? |
| IV | 红巨星 | — | 脱离主序，外层膨胀 | ?? | 3–?? |
| V | 红超巨星 | — | **普通超新星按钮解锁** | ?? | 3–?? |
| VI | 蓝超巨星 | — | ?? | ?? | 3–?? |
| VII | 沃尔夫-拉叶星 | WR | 顶级恒星，铁壁前的极限 | ?? | 3–26 |
| VIII | **中子星** | — | **中子素量产** | ??（最快） | 3–26 + 中子素 |

```
0 星云团 → I 红矮星 → II 橙矮星 → III 黄矮星 → IV 红巨星 → V 红超巨星
  → VI 蓝超巨星 → VII 沃尔夫-拉叶星 → VIII 中子星
       → 【超新星重启 + 点满约束 + 互斥升级】
            ├─ 抗扭曲升级 → 灌爆 → 黑洞（纯发电）
            └─ 质量控制     → 可控超新星（耗电，全元素等离子体）
```

**中子星必须放在主干（顶级之下、分支之上）**，不能放进分支：
否则走黑洞的玩家永远拿不到中子素量产，"取向选择"就退化成"内容阉割"。

### 2.1 铁壁

元素序号 26（铁）是聚变净能量由正转负的拐点。**任何恒星类型都过不去。**
跨越铁壁的唯一手段是**普通超新星**（§4.1）。

## 三、配方族（固定 3 条，不按元素展开）

| 配方族 | 输入 | 输出 | 作用 |
|---|---|---|---|
| **主序燃烧** | 氢 + 氦（氦调温） | EU | 保底发电；能量曲线按恒星类型放大 |
| **元素合成** | 氢 + 氦（+ 可选自回流等离子体） | 3–26 号等离子体，区间上限由恒星类型决定 | 物质生产主力 |
| **中子素量产** | 氢 + 氦（+ 可选回流） | 中子素（锭/板/框架） | **仅 VIII 中子星**；把 32mB/次的聚变产物变成持续供应 |

- 矩阵规模 **8 层 × 3 条 = 24 条**，不含每个元素单独成条。
- "全元素周期表"按**整合包内已注册的等离子体**为上限，不硬编码 1–118，
  避免产出"有配方能产、没配方能用"的死产物。

## 四、质量状态机

### 4.1 普通超新星（V 级以上解锁）

- **交互**：GUI / 结构上的确认按钮，需玩家主动激活（二次确认）
- **条件**：恒星等级 ≥ V，质量 ≥ ??
- **效果**：质量清零，恒星回到 I 级，**从头培育**
- **产出**：跨过铁壁的重元素（26 号以上）
- **可重复**：是。每次都要重新养一轮

### 4.2 终局抉择（VIII 中子星 + 一次超新星 + 点满约束）

两条分支**前置完全相同**，只在互斥升级里二选一。没有优劣，只有取向。

#### 分支 A：黑洞

```
前置：完成一次超新星 → 约束能力点满 → 选「抗扭曲升级」
描述：「抵抗空间任意尺度的扭曲，提供足够的安全性」
效果：质量上限被解除（改为"标称质量"判定）
操作：灌入超过约束能力标称的质量
结果：坍缩 → 黑洞
终态：纯发电，不产任何元素
```

#### 分支 B：可控超新星

```
前置：完成一次超新星 → 约束能力点满 → 选「质量控制」
描述：（待定文案）
效果：质量区间焊死为 [0, ∞)，永久关闭坍缩与轻而易举判定
操作：灌入氢氦 → 直接转化为重元素 / 超重元素等离子体
结果：可控超新星，不论灌入多少原料都不会引发坍缩
终态：耗电，产全元素周期表对应等离子体
```

**设计要点**：两条分支使用**同一个动作**（灌质量），却有两套相反语义 ——
抗扭曲下"灌爆"是主动求坍缩，质量控制下"灌多少"都只是投料。
「抗扭曲」的文本是**误导性的**：听起来是安全升级，实际是为了能安全地把它炸掉。此设计保留。

（外壳等级 / 磁约束线圈 / 结构层数，具体待定）。

## 七、实现风险清单

### 7.1 已确认可行的地基

- ✅ **枚举型机器模型属性原生支持**。`GTMachineModelProperties.VENT_DIRECTION` 就是
  `EnumProperty<RelativeDirection>`，模型侧 `.condition(VENT_DIRECTION, relative)`，
  `SimpleSteamMachine.onLoad()` 读同步字段后 `setRenderState(renderState.setValue(...))` 刷新。
  → **恒星类型用 `EnumProperty<StarClass>` 即可**，切换类型就是改一个状态位。
- ✅ **自定义配方类型 + 多方块控制器**已有先例（热力反应釜、焦炉仓）。

### 7.2 明确的风险点

| 风险 | 说明 | 对策 |
|---|---|---|
| **枚举状态数膨胀** | 每个枚举值烘焙一份模型，且与 `IS_FORMED`/`IS_ACTIVE` 相乘 | 8 类 × 2–3 布尔 ≈ 几十个状态，可接受。**禁止再叠第二个枚举**（会平方爆炸）；演化阶段用整数 NBT 字段 |
| **质量不能做成模型属性** | 100 档质量 = 状态数爆炸 | 质量的视觉表现（膨胀/收缩）走 `DynamicRender` 渲染时读实时字段改几何；换贴图才用状态位 |
| **模型烘焙与 NBT 的关系** | 机器模型按状态烘焙，不能每帧换贴图 | 沿用 `tools/gen-thermal-reactor-assets.py` 的探针式生成器；**不要手写 JSON**（上次黑紫贴图的老坑） |
| **等离子体 I/O 数量** | 热力反应釜是 `2 item / 3 fluid in / 2 item out / 2 fluid out` | 每级配方只产 1–2 种；**不要试图一个配方吐 24 种** |
| **能量双向** | GTCEu 机器 EU 方向是声明式的 | 见 §6.1 |

- ⏳ 配方类型仍是 `GTRecipeTypes.FURNACE_RECIPES`（纯粹为了不让成型崩溃，**不是真实配方**）
- ⏳ 恒星本体（OBJ 动态球体）尚未渲染
- ⏳ 约束能力、事故判定（轻而易举 / 坍缩）、抗扭曲与质量控制分支均未实现
- ⏳ 能量链只写了一半：等离子体已经能产，但**「等离子体 → EU」那一端还没有对接
